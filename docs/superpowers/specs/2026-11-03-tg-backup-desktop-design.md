# TG Backup Desktop — תוכנית

## הקשר
המשתמש רוצה תוכנת Windows בריפו חדש, עם כל מה שיש באפליקציית TG Backup. המטרה: לעקוף את הריגת האפליקציה ברקע ואת מגבלות המקום והסוללה בטלפון. התוכנה מיועדת גם לאנשים לא טכניים, ורצה אצל כל אחד על המחשב או השרת הביתי שלו, בלי ענן משותף. שליטה מרחוק מהטלפון תהיה דרך Tailscale עם סיסמה. אפליקציית האנדרואיד לא משתנה.

## החלטות המשתמש
- Windows בלבד, עם חלון תוכנה נפרד.
- כל משתמש מזין API ID ו-API Hash משלו, כולל הסבר בתוך התוכנה.
- משימות מהטלפון מוגדרות מחדש ידנית, עם "התחל מהודעה".
- קובץ התקנה מ-GitHub, והתוכנה מודיעה כשיש גרסה חדשה.

- **תוכנה רגילה:** קובץ התקנה `TGBackup-Setup.exe` מתקין את `TGBackup.exe` עם קיצור דרך, ו-Java כלול בהתקנה.
- **הכול בתוך התוכנה:** המנוע, החיבור לטלגרם, המסכים והשרת הפנימי. אין ענן ואין שרת חיצוני.
- **חלון משלה:** `TGBackup.exe` פותח חלון עם שם וסמל משלו, בלי דפדפן ובלי Edge. בתוכו רכיב תצוגה מובנה, למשל JCEF, שמציג את המסכים מהשרת הפנימי של התוכנה. הטלפון רואה אותם מסכים דרך Tailscale.
- **מראה כמו האפליקציה באנדרואיד:** ערכת נושא כהה, ניווט תחתון (משימות, ייצוא, חשבונות, לוג, הגדרות), אותם כרטיסים, מתגים וטקסטים בעברית. ב-UI מתאימים את מסכי `ui/*Screen.kt` של האפליקציה.
- **סמל ליד השעון:** פתיחה ויציאה. סגירת החלון ב-X לא עוצרת משימות.
- **הפעלה אוטומטית עם Windows:** מתג בהגדרות, כבוי כברירת מחדל.
- **בלי תעודת חתימה:** אזהרת SmartScreen בפתיחה הראשונה מוסברת בהוראות, עם "מידע נוסף" ואז "הפעל בכל זאת".

## החלטות שלי (לבדיקת המשתמש)
- רכיב התצוגה ייבחר בספייק (שלב 2), לפי גודל התקנה ויציבות. גודל ההתקנה הצפוי הוא כמה מאות MB, ועוד לא נמדד.
- **Stack:** Kotlin/JVM 17, Ktor, kotlinx.serialization, ו-`tdl-coroutines-jvm:15.0.0`, אותה גרסה כמו באפליקציה. נבדק: ה-JAR כולל `windows/x64/tdjsonjava.dll` ואת ה-DLL הנלווים.
- **ריפו:** `backuppppy/tg-backup-desktop`, **ציבורי**, כדי שאנשים יוכלו להוריד בלי חשבון GitHub. בלי סיסמאות, API או סשנים בקוד.
- **`export-core`:** מועתק לריפו החדש כמו שהוא (66,904 שורות, בלי תלות באנדרואיד). תיקונים עתידיים יועתקו ידנית בין הריפוים.
- **Sentry:** פרויקט חדש `tgbackup-desktop` בארגון `bubababa`, עם SDK רגיל (`io.sentry:sentry`).

## ארכיטקטורה
- **`export-core`:** ללא שינוי.
- **`engine`:** הקבצים מ-`app/src/main/java/org/tgbackup/app` של האפליקציה: `engine/*`, `data/*`, `tg/*`, `export/*`. צריך רק להחליף תלויות אנדרואיד: `android.os.Build` ב-`AccountClient.kt` וב-`ExportManager.kt`, נתיבים ואחסון, `AndroidImageThumbs.kt` ל-Java ImageIO.
- **`server`:** Ktor עם REST ו-SSE לסטטוס וללוג, במקום `BackupService.kt`.
- **`web`:** מסכים שנראים כמו באפליקציה (`ui/JobsScreen`, `ExportScreen`, `AccountsScreen`, `LogScreen`, הגדרות), מתאימים לחלון ולרוחב טלפון.
- **`desktop`:** נקודת כניסה של `TGBackup.exe`, חלון עם רכיב תצוגה מובנה, סמל ליד השעון, מופע יחיד, נתונים ב-`%LOCALAPPDATA%\TGBackup`.
- **כללים שנשמרים:** `JobRunner` ו-`TakeoutJobRunner` לא נוגעים זה בזה, וכללי `project_tg_backup_takeout_rules.md` חלים גם כאן.

## גישה מרחוק
- כברירת מחדל מאזינים רק על `127.0.0.1`. "גישה מהטלפון" היא מתג: המשתמש קובע סיסמה, והתוכנה מאזינה גם על כתובת ה-Tailscale (`100.64.0.0/10`), לא על כל הרשתות.
- ההזדהות היא סיסמה מגובבת, עוגיית סשן והאטת ניסיונות כושלים. לא פותחים פורט בראוטר.
- מסך הגדרות מציג הוראות קצרות וכתובת להעתקה. בלי Tailscale התוכנה עובדת במחשב בלבד.

## שלבים
1. **יצירת ריפו ו-CI:** ריפו, Gradle, העתקת `export-core`, בנייה ב-GitHub Actions.
2. **ספייק:** טעינת TDLib, חיבור והתחברות על Linux כאן, ובדיקת טעינת ה-DLL ב-`windows-latest`. באותו שלב: חלון עם רכיב תצוגה מובנה ומדידת גודל ההתקנה. אלה הסיכונים הראשונים, אז בודקים אותם לפני הכול.
3. **העברת המנועים:** העתקת `engine`, `data`, `tg`, `export` לריפו החדש, כך שכל הפיצ'רים הקיימים יעבדו גם במחשב. האפליקציה בטלפון וגם הריפו שלה לא נוגעים בהם.
4. **שרת וממשק:** חשבונות, משימות, ייצוא, לוג, הגדרות, והשוואת פיצ'רים מול האפליקציה.
5. **חוויית Windows:** חלון, סמל ליד השעון, מופע יחיד, הפעלה אוטומטית, מסך הסבר ראשוני ל-API.
6. **גישה מרחוק:** מתג, סיסמה, האזנה מוגבלת, מסך הוראות.
7. **התקנה:** `jpackage` ליצירת `TGBackup-Setup.exe` עם Java מובנה, Release אוטומטי ב-CI, בדיקת גרסה חדשה מול GitHub Releases, Sentry.

העבודה מתבצעת עם Superpowers וסוכנים. לכל גרסה: commit, push ו-release, והמסמכים נשמרים בריפו.

## מגבלות שיוצגו למשתמש
- המחשב חייב להיות דלוק כדי שהמשימות יתקדמו. עם ההדלקה הן ממשיכות מהמיקום השמור.
- צריך להתחבר מחדש לכל חשבון, וסשן הייצוא עשוי לדרוש אישור והמתנה של עד 24 שעות.
- Windows SmartScreen יזהיר בפתיחה הראשונה של כל גרסה, כי אין תעודת חתימה (המשתמש החליט לא לקנות).
- מגבלות טלגרם עצמן לא משתנות.

## אימות
- בדיקות JVM: `export-core`, סינון ערבית, דיווחים, חלוקת סבבים, הזדהות ואיזון האזנה.
- בדיקת הממשק ב-Playwright על Chromium, ברוחב מחשב וטלפון, מול השרת שרץ כאן.
- בדיקה חיה לקריאה בלבד עם סשן בדיקה.
- ב-CI על `windows-latest`: בניית `TGBackup-Setup.exe`, התקנה שקטה, הפעלה ובדיקת `/health`.
- השוואה חזותית של המסכים מול צילומי האפליקציה באנדרואיד.
- בדיקה סופית על Windows אמיתי על ידי המשתמש: התקנה, התחברות, משימה, סגירת חלון, הפעלה מחדש וחיבור מהטלפון דרך Tailscale. אי אפשר להריץ את זה מהסביבה כאן.
